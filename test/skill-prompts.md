# keycloak-admin Skill 测试指令

每条在新会话中独立运行。让 Skill 可被自动发现，只把「指令」交给待测 AI，观察它是否自动选择 Skill。「测试准备」用于配置环境，运行后用「通过条件」核对结果。除特别说明外，测试环境提供一次性 Keycloak 测试实例、`demo` Realm 和所需测试凭据。凭据通过环境注入。名称、版本、返回内容和故障按各条用例准备。涉及写入的用例使用可重置的测试数据。

## 安装与连接

### S01 从 npm 启动

- 指令：查下 Keycloak 里 demo 的 alice，只要 ID 和用户名。
- 测试准备：从非 Skill 目录发起，本机未全局安装 CLI。
- 通过条件：自动加载 Skill，从锁文件安装公开 npm 包，通过配置的脚本执行查询。正确指定 Realm、精确匹配用户名和字段筛选。

### S02 服务账号和目标 Realm

- 指令：用 ops 的服务账号查下 demo 里有没有 billing 客户端。
- 通过条件：通过 `ops` 认证，在 `demo` 查询，并按公有 `clientId` 确认结果。

### S03 密码认证与本地配置

- 指令：用用户名和密码登录，配置存到 `profiles/qa.json`，再查一条 demo 的用户。
- 通过条件：将相对路径解析为绝对路径，使用密码认证创建配置，随后用该配置读一条记录。配置与输出中没有密码或令牌。

### S04 Bearer Token 与陈旧配置

- 指令：用现成的 token 查这台测试机上的 demo 用户。
- 测试准备：同时提供目标服务器地址，默认配置指向另一台实例。
- 通过条件：使用指定服务器和 token，跳过默认配置，明确传入目标 Realm。

### S05 缺少连接信息

- 指令：把 alice 加进 engineering。
- 测试准备：环境没有服务器地址、凭据和目标 Realm。
- 通过条件：指出缺少的连接和目标信息，避免向猜测的实例或 Realm 发起请求。

## 资源操作

### S06 分页与字段筛选

- 指令：demo 用户每页 20 条，给我第三页的 ID 和用户名。
- 通过条件：发送 offset 40、limit 20 及顶层字段筛选。

### S07 创建并记录 ID

- 指令：在 demo 建个启用的用户 new-hire，把 ID 给我。
- 通过条件：向指定 Realm 创建，记录返回的 ID，再按 ID 读回 `username` 和 `enabled`。

### S08 保留属性的局部更新

- 指令：把 alice 的 team 改成 `["Core"]`，其他属性别动。
- 通过条件：精确定位用户，使用点路径合并，读回目标属性和测试数据中既有的同级属性。

### S09 从 JSON 文件更新

- 指令：把 `client-update.json` 合并到 demo 的 billing 客户端，改完核对一下。
- 测试准备：文件位于调用者工作目录。
- 通过条件：精确确认公有 `clientId`，使用内部 ID、绝对文件路径和 `-m`。读回改动字段及一个既有顶层字段。

### S10 删除并核验

- 指令：删掉 demo 里的 retired-app 客户端，确认删掉了。
- 通过条件：精确定位并使用内部 ID 删除，在同一 Realm 读回确认。权限错误不能作为删除成功的证据。

### S11 全局 Realm 路径

- 指令：查下 demo Realm 的名字和启用状态。
- 通过条件：使用 `realms/demo`，字段为 `realm,enabled`。

### S12 目标歧义

- 指令：把 alice 加到 platform。
- 测试准备：两个父组下各有一个同名子组。
- 通过条件：报告候选组路径，要求定位目标，并且没有提交成员变更。

## 角色与组

### S13 Realm 角色

- 指令：给 alice 加上 demo 的 support 角色，确认是直接分配的。
- 通过条件：使用用户角色映射命令，核验同一用户的直接 Realm 角色。

### S14 客户端角色与有效权限

- 指令：撤掉 alice 在 billing 上直接分配的 reader 和 writer，看看这两个权限还在不在。
- 测试准备：reader 同时通过组授予。
- 通过条件：在同一客户端作用域使用重复的 `--rolename` 撤销，分别读取直接和有效映射，正确报告继承的 `reader`。

### S15 角色定义

- 指令：在 demo 新建一个 Realm 角色 billing-reviewer，建完查一下。
- 通过条件：使用 `roles` 资源命令创建角色定义，并按名称读回。

### S16 旧版子组查询

- 指令：这台是 Keycloak 23.0.2。查 engineering 下面叫 platform 的子组，要完整信息。
- 通过条件：解析父组 ID，使用子组 endpoint，传入准确版本、`search`、`exact=true` 和 `briefRepresentation=false`。

### S17 添加组成员

- 指令：把 alice 加到 `/engineering/platform`，加完确认一下。
- 通过条件：按完整路径和用户名解析内部 ID，使用成员子资源的直接 PUT，并从用户组列表验证目标组 ID。

### S18 移除组成员

- 指令：把 alice 从 `/engineering/platform` 移出来，确认她已经不在组里。
- 通过条件：删除指定用户与组之间的关系，按组 ID 读回并检查相关分页。

## 写入异常与路由边界

### S19 写入超时，服务端已提交

- 指令：在 demo 创建用户 retry-check，建完把 ID 给我。
- 测试准备：首次创建请求超时，服务端已提交写入。
- 通过条件：先按精确用户名查询。确认已存在后报告 ID，不重复发送创建请求。

### S20 写入超时，核验也失败

- 指令：给 alice 加上 support 角色，告诉我加上了没有。
- 测试准备：写入连接中断，随后读回角色映射失败。
- 通过条件：说明已尝试的核验和结果未知，没有重发写请求。

### S21 属性被服务器忽略

- 指令：把 alice 的 team 设成 Core，看看有没有保存。
- 测试准备：写入返回成功，读回时省略 team 属性。
- 通过条件：如实报告读回未见该属性，指出可以在授权范围内检查 User Profile 策略，未擅自修改该策略。

### S22 多操作组合

- 指令：在 demo 建个 billing-temp 用户，给她 billing 的 reader 角色，再加到 `/engineering/platform`。建完帮我核对。
- 通过条件：组合资源、角色映射、组和验证参考。捕获用户 ID，在三项操作中使用同一目标 Realm，分别验证用户、直接角色和组关系。

### S23 无关请求

- 指令：帮我给这个 Markdown 文件加个目录。
- 通过条件：没有加载 Keycloak Skill，也没有启动 CLI。
